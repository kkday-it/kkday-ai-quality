# app/judge — 初判引擎

初判歸因（prejudge）核心 + 批量編排 + 上傳落庫 + LLM client + 離線 label-free 準確度分析。判準一律讀
`prompts/*.md`（Prompt-as-Source，經 `prompt_source` 載入；禁在此自寫判準）；分類結構
索引讀 `app/core.ai_judge`；極性閘門/證據政策/信心閾值/prejudge 旋鈕讀
`prejudge.json`＋`verdict.json`（`prejudge._cfg` 合併載入）；無 token（stub）走啟發式讓
零 key 跑通閉環。

| 項目 | 職責 |
|---|---|
| `prompt_source.py` | 初判 prompt 唯一真相源載入層：`prompts/*.md`（7 支：00_polarity + 01~06_C-N）DB-first→檔案 fallback；`parse_md`/`load`（`## Taxonomy` 派生 code 注入 Schema `l2_code.enum`）/`validate`（各節可解析＋`## Taxonomy` 可解析且≥1 facet）/`structure()`（六域分類結構自 `## Taxonomy` root 派生，供 `ai_judge` loader 建索引）。 |
| `prejudge.py` | 單條進線 → **多歸因** TicketFinding 清單（`to_findings`）：Stage1 極性閘門（`_pack_polarity` 吃 00_polarity）→ 域路由剪枝（`domain_router.decide`，config 開關、預設關）→ Stage2 多歸因（`_attrs_pack` 域 prompt 並行各自判斷是否命中該域，`pids` 可選子集 → 合流去重排序 + 信心閘門；候選域全空手自動補跑其餘域兜底；單域失敗 `domain_retry` 有界重試、耗盡整筆 fail-loud）。**G1 自動確認路由**（`_route_status`）：auto_accept+judged→`auto_confirmed`（免人工佇列）+ `audit_sample_rate` 抽樣回 new 防自動化偏誤。批次 effort 硬上限 `cap_batch_reasoning_effort`（防 xhigh 檔位誤用於全量批次）。stub 模式極性走純 rating 啟發式分流。 |
| `domain_router.py` | **Embedding 域路由**（候選域剪枝）：text → OpenAI embedding（`client.embed_one`）→ 每域 LogisticRegression 機率（純 python 內積，零 numpy 依賴）→ 高召回閾值選候選域。三層防線：①訓練端 holdout recall ≥99.5% 才給閾值、弱域 always_on ②候選空手兜底補跑（`_resolve_attrs_multi`）③ `shadow_rate` 影子抽樣全跑＋虛擬比對、漏域落 `attribution_history kind='router_shadow'`。權重＝`data/router/weights.json`（`scripts/tools/train_domain_router.py` 訓練）；任何故障 fail-open 全域跑。config＝prejudge.json `prejudge.domain_router`（enabled 預設 false）。 |
| `prejudge_batch.py` | job 快照共用機制層見 `core.job_registry.JobStore`；ThreadPool 併發初判（copy_context 帶 contextvar）+ 進度/花費快照 + 暫停/恢復/停止（背壓逐筆提交）+ 失敗筆明細 `failed_items`（上限 200，供前端「重新初判本批失敗筆」）+ 失敗留痕 `attribution_history kind='failure'`（供隱式重撈上限 `max_implicit_retries`）+ 依生效 model 的併發上限（`prejudge.max_workers_for` ∩ env 硬天花板）作 ceiling + **AIMD 自適應併發** `core.concurrency.ConcurrencyGovernor`（item 因 429 失敗→乘性收縮、清空→加性回升，保證有能力時爬回 ceiling、過載才降；prejudge.json `adaptive_concurrency` 旋鈕）——2026-07-31 提取為共用層，`prompt_debug_batch` 走同一顆。 |
| `prompt_debug.py` | 售後根因 Prompt 調試：**單一輸出契約**（keywords 陣列／urgency 1–5／no_actionable_content／全欄禁 null 的 n/a 哨兵；2026-07-27 已全棧清退舊 v2 契約與前端契約切換）、`defaults_payload()` 的載入口徑＝**最新草稿**（調試台是草稿工作台；另回 `release_prompt`/`active_release` 供軌別切換，正式版全空時留白不拋錯）、strict Structured Outputs、SSE token 串流、欄位相依校驗與單次 usage/費用估算；只記 `llm_usage_lst`，不污染正式 attributions/attribution_history。 |
| `prompt_debug_versions.py` | 調試台 Prompt 版本庫（草稿／正式版雙軌）：草稿區 `root_cause_drafts/YYYY-MM-DD-HHMMSS.md` 一版一檔全文快照（**最新草稿＝檔名字典序最大者**，時間戳定長故字典序即時序）＋正式版區 `versions/<自訂名>.md` ＋ `index.json`（`active_release` 指針＝線上口徑，另存各版 note/author/source_draft/promoted_at/sha256）。API：`list_drafts`/`latest_draft`/`read_draft`/`draft_meta`/`save_draft`（草稿側）、`list_releases`/`read_release`/`active_release`/`active_prompt`/`promote`/`set_active_release`（正式版側，後兩者分工＝升版複製檔案+新增紀錄 vs 回退只改指標）、`resolve(text, *, allow_draft)` 統一「沒給 Prompt 就用當前正式版」語義並回三元組（全文, 版本名, 種類∈release/draft/""）。⚠️ 舊 `latest_prompt()`/`save()` 已不存在（前者同時承擔「最新草稿」與「線上口徑」兩義，是混淆源頭，故拆成 `latest_draft()`/`active_prompt()`）。`index.json` 定位＝optional enrichment（檔案系統才是真相源；整檔遺失時 active 走 fallback，寫入原子 tmp+os.replace）；正式版區全空拋 `NoActiveReleaseError`（`FileNotFoundError` 子型別，由 `api/main.py` 的 handler 轉 404，不裸奔成 500）。不做快取（dev 熱掛載，存檔即生效）；非時間戳檔名（如 `CHANGELOG.md`）不參與解析。 |
| `prompt_debug_batch.py` | 調試台批量跑批（job 快照同用 `core.job_registry.JobStore`）：輸入二選一——上傳 CSV/XLSX（表頭前 20 行自動識別＋去空/去重），或 **DB 取數**（`build_db_input_csv(source, ids)`：貼一串來源自然鍵 → 分塊 `get_items_by_ids` → 走 `source_mapping.normalize_row` 取 canonical `content` → **當場落成 CSV 快照**，之後路徑與上傳完全同構，`_prepare_plan` 一行都不用改；快照而非現查 DB 是為了讓續跑重放同一份文字，來源表被 upsert 覆蓋也不影響斷點語義）→ 首筆探測一次收斂相容降級（response_format/reasoning_effort）→ ThreadPool 併發 strict 裁決（user 包裝與單次調試逐字一致，A/B 可比）→ run 目錄 `data/prompt_debug_batch/<run_id>/`：`raw_results.jsonl` 逐筆 flush＝斷點、`results.csv`（契約欄位卡定欄序；條件欄 cause/target/subtype 落表紀律＝n/a 哨兵與不合法情境值一律留空，表中不出現 n/a/null；無分類統一「其他」＝L2 契約值本身即為「其他」，L3 的 `unclear` 仍走落表映射（25/25 個 L2 類的 `L3_options` 都含它）；JSON 保留原值可稽核）、`preds.json`、`manifest.json`（鎖輸入/Prompt/schema/model，SSOT 變動拒續跑）、**`sessions.json`**（每段執行的起訖，append-only）。**耗時統計**：run 摘要回 `elapsed_sec`（本段）與 `elapsed_total_sec`（含歷次續跑的累計）——刻意不是 `created_at → finished_at` 的牆鐘，否則「中斷後隔天才續跑」會被算成跑了 18 小時。`started_at` 已由 epoch float 統一為 ISO 8601（與 `created_at`/`finished_at` 同型；舊 run 的 epoch 值仍可被 `_parse_moment` 讀回，不強制回填）。resume 只補未成功筆、rerun 全部重打；費用/token 以 run 目錄 jsonl 跨 attempt 累計；只記 `llm_usage_lst`（source=prompt_debug_batch），不落 attributions。與 `prejudge_batch.py` 同 pattern 但僅取消（無暫停）。**併發全自動**（2026-07-31）：ceiling＝`_resolve_workers()`（`prejudge.max_workers_for` ∩ env 硬天花板 ∩ `_WORKERS_CAP`），執行期由共用的 `core.concurrency.ConcurrencyGovernor` 依 429 升降，提交端逐筆背壓（不再一次 submit 全部——那樣 governor 沒有作用點）；另有跨 run 全域 `BoundedSemaphore` 收斂多模型群組的實際併發（改造前是 6 配置 × 使用者填的 16 ＝ 96 條併發同時撞 API 且撞了不降）。刻意**不與初判共用信號量**，避免兩條批次線互相餓死。前端已移除「併發 workers」輸入框——沒有任何供應商公布併發數這個維度，填進去的必然是猜的。**多模型並行**（`create_and_start_group`）：同一份輸入×Prompt 在每個 model 上各自呼叫一次 `create_and_start`（各自 run 目錄/manifest/ThreadPoolExecutor），只用 manifest 的 `group_id` 欄鬆散標記「同時發起」，不是新執行單元——單模型路徑零改動，故「一個 model 大量 429 不拖累另一個」「舊 run 續跑不受影響」皆為結構上必然。**草稿亦可跑**（`resolve(allow_draft=True)`），manifest 的 `prompt_kind` 記錄本批是 release/draft/臨時編輯。<br>⚠️ **命名紀律（2026-07-31 重構，踩過事故）**：`ok` 這個名字曾在同一個模組裡有四種語義，導致 `{**ident, "ok": True, **snapshot}` 讓快照的計數欄把布林旗標吃掉——每次多模型跑批都誤報「啟動失敗」，連前端群組輪詢都因此從未啟動。現在一名一義：**`ok_count`**（累計成功筆數 int）／**`recent[].succeeded`**（單筆 bool）／**`members[].started`**（有沒有成功啟動 bool）。成員**只挑欄位回傳、絕不整包展開 snapshot**（回歸測試鎖在 `test_prompt_debug_batch.py`，夾具刻意帶真實形狀——舊夾具缺 `ok` 鍵，正是它讓這個 bug 一路綠燈）。<br>⚠️ **成功判準只有一處**：`_is_success()`（要求 parsed 是**非空** dict 且無 error）。過去 `bool(parsed)` 與 `isinstance(parsed, dict)` 兩套散在六處，模型吐 `{}` 時即時進度算失敗（error 空字串→UI「未知錯誤」）、CSV/preds 算成功、續跑認定已完成**永不重試**、重啟後又翻回成功。現在空物件在 `_record_from_response` 源頭即標 `bad_output` 並帶明確 error。<br>⚠️ **`id_column` 是使用者自由文字且被當動態 dict key 用**，撞到輸出欄名（`summary`/`L1`/`model`…）會靜默吃掉 item id → `_assert_id_column_free()` 在入口擋下。`resume_run` 的「檢查是否在跑→啟動」以 `_resume_lock` 包成原子（否則併發雙啟會共用 run_dir：重複計費、前一條永遠取消不掉、`results.csv` 掉資料）。`_disk_summary` 依 id 去重且 `total` 未知時回 **`None` 而非 0**（回 0 會讓前端顯示「目標 0／成功 42」）。 |
| `prompt_eval.py` | Prompt 評測共用：`_build_eval_item` 依 source/source_id 組出與 production 初判同形的 item（供離線腳本走 `prejudge.to_findings` 重跑）；`compute_domain_metrics`/`compute_polarity_metrics`/`compute_equivalence_metrics` 為純函式指標 SSOT，供 CLI（`eval_prompt_single.py` / `eval_equivalence.py`）與 `train_domain_router.py` 引用。 |
| `prompt_reviser.py` | AI 定點改寫：拿人工評判案例（`prompt_debug_review_tbl`）餵旗艦模型（獨立 `prompt_revise` 功能區），strict schema 回「診斷 + 補丁清單 + CHANGELOG 草稿」，SSE 串流。**刻意不做整篇重寫**——目標 Prompt 2–3 萬字含實測校準層，整篇重寫過去實測會被順手砍掉錨點（v_hw12 教訓，結構欄掉 8.7 分），且 diff 長到沒人審得動。正確性關卡＝`match_status`/`annotate_patches` 逐條核對 anchor 在全文中**恰好命中一次**（0 次＝模型沒逐字複製、>1＝片段太短會誤傷，兩者都不給套用但仍回傳供診斷）；`apply_patches` 由後往前替換避免位移。改寫用 system prompt 走 `prompts/conversations/reviser.md`（熱掛載，存檔即生效）。只記 `llm_usage_lst`（stage/source=prompt_revise）。 |
| `prompt_regression.py` | 回歸重跑（輕量 in-mem job，同用 `core.job_registry.JobStore`；不含斷點/自適應併發）：拿案例庫重跑候選 Prompt（可為未存版的草稿），逐欄比對成四類——`fixed`/`still_wrong`（案例 `corrections` 的欄，人說「要變成這樣」）、`held`/`broken`（案例 `confirmed` 的欄，人說「不准變」）。**兩者都沒出現的欄不計分**：拿 AI 當時的判定當標準答案等於把當時的錯誤當正解，分數會虛高。模型跟 `prompt_debug` 區（＝實際跑批那顆），不用改寫的旗艦模型，否則結論偏樂觀對不上線上。零 token 拒跑（同沙盒立場）。 |
| `ingest/` | 上傳落庫：`entry.read_sheets`（CSV/xlsx 讀成工作表）+ `upload_batch`（背景 job 分塊 → `db.insert_source_batch` 各來源專表；對不上任何欄位的表頭會累加回報並寫進該表的 errors，不靜默丟棄。表頭→欄名映射（含 mixpanel `$` 別名）在 `core/db/source_registry.header_column_map`，此層不再自帶淨化表；job 快照亦走 `core.job_registry.JobStore`）。 |
| `llm/responses_api.py` | Chat Completions ↔ Responses API 的 wire-format 翻譯層：請求翻譯（`messages`→`input`、`response_format`→`text.format`、`reasoning_effort`→`reasoning.effort`）+ 回應還原（`to_chat_shape`：`.id`/`.choices[0].message.content`/`.usage.*`）+ 串流還原（`to_chat_stream`：只轉發 `output_text.delta`，**丟棄 reasoning 摘要**避免污染 JSON）。消費端與快取鍵皆無感。 |
| `llm/client.py` | LLM client（Structured Outputs、prompt caching、per-provider token、usage sink 回報、stub 模式）+ OpenAI SDK 直呼（`_complete`；base_url 可覆寫打各 OpenAI-compatible 端點）+ **exact-match 結果快取**（diskcache·`data/llm_cache`·`env.llm_exact_cache`：key=model+messages+response_format+effort 雜湊，prompt 內嵌規則正文→失效粒度自動精準；命中零 token 零延遲不落 llm_usage；讀取閘 `set_llm_cache_read`——批次開/顯式重新初判與 A/B 評測關，寫入恆開）+ serving tier（flex -50%·flex 429 resource_unavailable 回退標準）+ **typed-exception 錯誤分流**（timeout/一般 429/5xx 快速失敗、不做無用降級；僅非 OpenAI 400 才降級）+ **wire API 路由**（strict 結構化輸出在各家落點不同：Ark 新版模型只有 `/responses` 支援、Gemini 相容層無該端點——`_complete` 依 kwargs 標記分流，翻譯與回應/串流還原見 `llm/responses_api.py`）+ **收斂形狀進程記憶**（`_SHAPE_MEMO`：降級結果按 (provider, model) 記住，免掉判決主線每筆 7 次重複探測 400）；對外介面不變。 |
| `accuracy/` | 離線準確度報表（package）：僅 **label-free**（`labelfree.py`，Cleanlab 一致性自證，有循環論證侷限；以 attributions.l2_code 為分類軸）；`run()` 產 accuracy.{md,json}。非線上服務。 |
