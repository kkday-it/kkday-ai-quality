# config — 前後端共用配置 SSOT（業務可調·非機密）

前後端**同讀同一份 JSON**：後端 `app.core.paths.CONFIG_DIR`（`GLOBAL_DIR`/`AI_JUDGE_DIR`），前端 `@config` alias。
機密走 `backend/.env`，固定參照字典走 `constants/`（見決策樹 `.claude/rules/config-and-hardcode.md`）。

## global/（業務可調·跨環境）
- `retention.json` — **資料保留期政策**（維運可調，改此檔即生效）：`llm_usage_lst` 逾期天數 / `prejudge_run_tbl.log` 置 NULL 天數 / `attribution_event_lst` 每組保留的 prejudge 快照數與 failure 清理開關 / 跑批產物目錄逾期天數。消費者＝`scripts/ops/retention.py`（預設 dry-run）。每項附 `_rationale` 說明「這份資料在什麼時間點後不再有人讀」，訂閾值前先看它
- `llm_model.json` — LLM providers 目錄 + defaultModels + per-model 單價（pricing loader / 前端下拉共用）+ 根層 `embeddings[]`（embedding 模型單價，域路由特徵用——僅計價、不進聊天模型下拉）+ 根層 `areas[]`（LLM 消費功能區清單：prejudge / prompt_debug / prompt_revise）+ 根層 `modelConfigs[]`（**全新環境的初始模型配置**：每筆 `{id,provider,model,thinking,reasoning_effort,temperature}`，由後端 `settings._blank_settings()` 種入 DB，之後就是一般配置、與使用者自建的零差別——**沒有出廠層**，不存在唯讀／複製／還原出廠。⚠️ **不含 `name`**：名稱由規格衍生（`settings.derive_config_name` ↔ 前端 `deriveConfigName`，兩端有黃金清單 parity 測試），落庫的只有五個旋鈕欄；名稱不落庫就不可能與規格漂移。唯一性判「規格重複」而非「名稱重複」（`spec_key`：折疊掉該供應商實際不生效的旋鈕後比對）。⚠️ 初始內容**只對「`llm_model_configs` 這個 key 不存在」的 row 生效**，既有 row 要補內容必須走 migration）+ 根層 `areaDefaults`（**該區還沒選過配置時的出廠起點**，值＝`modelConfigs` 的 id，如 `prompt_revise` 直接起在旗艦 `seed-openai-flagship`——各區合適的模型檔次差很多，裁決跑批要便宜、改 Prompt 要聰明，不能全共用一組；後端 `settings.area_default_knobs()`、前端 `LLM_AREA_DEFAULT_CONFIG_IDS` 同讀此欄；被指到的 id 可以刪除，刪除時後端會剪除指向它的綁定、該區回落到這裡的出廠起點（確認框會先講明後果）。⚠️ **不是「使用者當前選了哪個」**——那份是 DB `setting_master` 的 `llm_area_configs`（團隊共用單一份，功能區下拉選了就落庫），本欄只是「該區還沒綁過時」的起點）+ `modelCapabilities`（per-model 可配參數能力覆寫；未登記者回退所屬 provider 的 `supportsThinking`/`reasoningEffortOptions`/`temperatureLockedWhenThinking`/`lockedTemperatureValue` 欄位，後端 `settings.model_capabilities_for()` 讀取） + `providers[].responsesApi`（**該供應商有沒有 `/responses` 端點**：`supported` / `absent`；後端 `settings.provider_has_responses_api()` 讀取）。這是端點**存在性**的靜態事實，不是 per-model 能力宣告——per-model 走錯誤驅動探測 + 進程記憶（見 `client._wire_api_for` 一帶）。之所以必須靜態宣告：Gemini 相容層沒有 `/responses`，打過去回 **404 而非 400**，400 降級階梯攔不住。此欄同時是單一 kill switch：改回 `absent` 即關閉該供應商的 Responses 路徑，不需動程式碼
- `sources.json` — 5 來源清單（`sources[]`：`value` 機器值 → `label` / `hint` / `natural_key`；sources loader）
- `bd_tag_vertical.json` — 商品垂直分類：BD 分工代碼 → `{note, pm, vertical}`（bd_tag_vertical 默認 seed，源自 BD 分工表 Google Sheet）
- `qc_db.json` — QC DB 連線預設
- `permissions.json` — 無角色，email 直接授予 business-key 權限集合 SSOT：`no_auth_grant_all`（本地無登入時無條件全通過）+ `default`（人人可用的日常操作 key）+ `grants`（email → 額外 key 集合，`'*'` 展開為全量；key 定義見 `backend/app/core/permissions/permission_keys.py`；`LocalPermissionProvider` 讀此，`default ∪ grants[email]`）
- `auth.config.json` — 認證/權限 provider 切換開關：`authProvider`＝登入身分驗證（local=固定身分不驗 token｜be2=中央 Auth Service token）、`provider`＝權限來源（local=permissions.json 直接授予｜be2=Auth SVC business-list），兩鍵獨立可分開切換；`whiteList`（be2 免權限路徑預留）+ `businessListTtlMs`（前端權限清單快取 TTL）+ `be2` 段接入佔位（`authSvcUrl`/`be2LoginUrl`/`apiLangUrl`/`langPlatform`，實值待 auth team 註冊回填）
- `export.json` — 導出行為配置（前端消費）：`gdrive_upload_folder_url`＝導出完成通知「打開 Google Drive 上傳」捷徑的 config 內建最終回退資料夾 URL；實際生效值優先讀「設定 › 導出偏好」tab 配置的全項目共用一份（存 `setting_master` 的 `gdrive_upload_folder_url`，非 per-user；皆空＝退回個人 my-drive）

## ai_judge/（判準領域）
> **判準文字唯一真相源為 `prompts/*.md`**（Prompt-as-Source 架構，7 支：00_polarity +
> 01~06_C-N）。判準由 LLM 直讀各域 prompt 的 System 區塊，分類結構（域機器值/L2 面向）由
> `app.judge.prompt_source.structure()` 從 prompt 派生（不讀 DB 樹）。

- `prejudge.json` — **初判階段**配置（**專案靜態設定檔**，改值＝改此檔 + 重啟後端；與 `verdict.json` 由後端 `_read_stage_files()` 合併載入）：極性閘門（`polarity_gate.attribute_when`：哪些整體傾向進歸因）+ 證據政策（`evidence_policy`：`attr_min_confidence`/`secondary_min_confidence`/`require_quote_grounded` 閘門；證據閘域已移入各域 prompt `## Taxonomy` root evidence_gated）+ 信心分層閾值 + 傾向/分層/初判階段中文 label（`stage_labels`：judged=已初判/unjudged=未初判/pending_data=待數據補充/pending_review=待複審）+ prejudge 旋鈕（per-stage `*_reasoning_effort` 省 token 旋鈕：polarity／attribute，null＝沿用主 config；`batch_service_tier`：批次初判 serving tier，"flex"＝OpenAI flex processing -50% 計價換變動延遲、429 自動回退標準、`flex_min_items` 以下小批走標準；`max_workers_by_model`/`max_workers_default`＝依生效 model 分設批次併發上限，切旗艦模型自動降併發，實際再與 env.prejudge_max_workers 硬天花板取 min）+ `batch_max_reasoning_effort`（批次 job reasoning_effort 硬上限，預設 medium——防 xhigh 診斷檔位誤用於全量批次）+ `domain_router`（embedding 域路由剪枝：enabled 預設 false／shadow_rate 影子抽樣／embedding_model／thresholds／always_on；權重檔 data/router/weights.json 由 scripts/tools/train_domain_router.py 產出，任何故障 fail-open 全域跑）。＋ `pii_mask`（PII 輸入端遮罩：送雲端 LLM 前於 `prejudge._text_of` 唯一出口套用，`rules[{name,pattern,replacement}]` 依序 regex 置換——email/台灣手機/國際碼/10 位以上連號；刻意不遮訂單號/OID（判決佐證要用）；`enabled=false` 停用；公司「含 PII 外送雲端 AI API 需資安確認」慣例的工程防護佐證）。判官提示詞與域界線已全數移入 prompt md，本檔不再存。不納入 RuleManager 版本化編輯範圍。
- `verdict.json` — **G1 自動採納路由**配置（同為靜態設定檔，與 `prejudge.json` 合併載入）：`auto_confirm.enabled` + `audit_sample_rate`——信心達 auto_accept 且已判定的初判結果自動採納（`attribution_tbl.is_auto_accepted=true`），依比例抽樣不採納、留給人複審以防自動化偏誤。存檔前由 `rules.py` 強驗此塊完整（誤刪整塊會靜默退回 `enabled=True`，等於偷偷全開自動採納）。
- `evidence.json` — **訂單佐證（qc_evidence）子系統**旋鈕（靜態設定檔，純後端消費、前端不讀；改值重啟生效）：db（dbname/schema/connect·statement timeout/pool_size 併發上限/熔斷 threshold·cooldown）+ cache（`order_ttl_hours` 6·單一 TTL；快取落 PG `evidence_snapshot_tbl`，PK＝serial `evidence_snapshot_oid`、`order_oid` 上有唯一索引保「一訂單一列」，拆欄——ID/純量各自成欄、商品/規格/方案內容各自獨立 jsonb 欄，非單一 payload blob，TTL 懶清理）+ singleflight_wait_timeout_s + summary（`lang_fallback` 商品版本語系兜底，`order_tbl.lang_code` 缺值時用；⚠️ 同段的 `max_chars_per_field`／`max_total_chars` 目前**無任何消費端**，`summary_cfg()` 亦無呼叫者）。`enabled=false` 一鍵停用佐證取數（判決全走無佐證降級）。
- `after_sales_root_cause.json` — **售後根因分類庫 SSOT**（`app.judge.prompt_debug` 唯一消費者，供輸出校驗、級聯與裁判表摘要；調試台/跑批實際送出的 system prompt 走 `prompts/conversations/root_cause_drafts/`（草稿）與 `prompts/conversations/versions/`（正式版）的全文快照）。**當前版本 `2026-08-03`＝《根因標籤架構》表 260803 版**（六個表欄逐字轉錄，見 `sources.labeling_framework_table`）：6 個 L1（`L1_options`；含無代碼的「現場履約問題」，其 `code` 為空字串）× 24 個 L2（`L2_entries`：`L1_code`/`L1_label`/`name`/`definition`/`include`/`exclude`/`examples`/`L3_options`）+ `L4_options`（**兩個值域**：`modify_target` 供 [93] 四類、`oot_subtype` 供跳出分支）+ `fallback_cause_rule`。
  - 兜底值全表統一為「其他」（`unclear` 隨 260803 表退役）；跳出分支的 L1／L2／L3 三層皆「其他」，L4 改由 `oot_subtype` 承接（`no_actionable_content=true` 時固定 `對話殘段/無實質`）。
  - **本檔與 Prompt 快照必須同批升版**：schema enum／級聯／校驗全由本檔派生，Prompt 內嵌的是同一份表的快照。只升 Prompt 不升本檔，Structured Outputs 會把新表答案硬塞回舊 enum（2026-08-03 事故，見 `root_cause_drafts/CHANGELOG.md`）。兩道防線：repo 端 `backend/tests/test_prompt_debug.py::test_default_prompt_taxonomy_matches_contract_ssot` 守默認口徑；執行期 `prompt_debug.taxonomy_drift_warning()` 對**實際送出**的 Prompt（含歷史版本與頁面臨時編輯）比對後回警示（單次調試走 SSE `warning`、跑批寫進 run 的 `warnings`，不阻斷）。
  - 判準的**實測校準層**（`calibration`／`L3_guide`／`L4_guide`／全域規則 R1–R5）只存在於 Prompt 快照，本檔不留副本——同一段文字兩處存放必然 drift，且校驗器不消費它（260722 版曾在本檔並存 8 類 calibration，隨表改版一併清退）。
- `RootCauseLabelingFramework.json` — PM 維護的《根因標籤架構》原表轉錄（`taxonomy_version` `2026-07-28`；受控詞彙＋邊界判準＋`hard_rules`/`usage_notes`/`status_legend`）。**零 code 消費**——程式實際讀的是上一條 `after_sales_root_cause.json`（版本 `2026-08-03`），本檔僅供人查閱原始定義，兩者版本不同步時以 `after_sales_root_cause.json` 為準
- `source_mapping.json`（+`.schema`）— 5 來源欄位映射（源欄→canonical）+ 上傳指紋辨識／必備表頭校驗（已納入 RULE_CODES＝可經「規則配置 › 上傳表頭校驗」版本化編輯 + 存檔熱重載；本檔為初始 seed）
- `correction.json` — **人工糾正政策**（前後端同讀，避免兩邊漂移）：`editable_fields` 可改欄白名單（後端據此做寫入白名單、前端據此決定表單長什麼樣）+ `reason_min_length`/`reason_max_length` 理由長度門檻。⚠️ 刻意**不開放**改 `summary`/`evidence`——那兩欄是 LLM 的 grounding 產物（evidence 是逐字擷取原文的防幻覺錨點），人改過就再也分不清哪些是原文；`polarity` 也不在清單內，它由 `sentiment_score` 派生（區間 SSOT 在 `backend/app/core/schema.py` 的 `SENTIMENT_BANDS`）。
- `attribution_dimension.json` — **值域主檔的默認 seed**（真相源是 DB 表 `attribution_dimension_master`，業務可於「設定 › 判決值域」維護）：**四軸**——`responsible_party`（責任方，六個域的 `_meta.owner_role` 全空故為提案值、待業務確認）／`severity`（取自既有 `Severity` Literal）／`verdict_action`（取自既有 `RecommendedAction` Literal）／`note_type`（備註的互動類型：內部說明／已聯繫供應商／已聯繫旅客／待跟進／已解決）。`item_code` 是落庫的機器碼、改碼＝改歷史語義故禁改；`item_label` 可改，落庫時同存快照。
